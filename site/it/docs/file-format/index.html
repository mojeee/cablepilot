Formato del file di progetto

Cosa contiene un progetto .cablepilot.json: il formato JSON documentato, come è scritto per Git, versioni, migrazioni e formati di scambio.

  • Come funziona la numerazione
  • Formato del file di progetto

Un progetto CablePilot è un unico file di testo UTF-8 chiamato <nome>.cablepilot.json. È JSON semplice e documentato: puoi leggerlo, tenerlo in Git, confrontare due versioni riga per riga e scrivere i tuoi strumenti intorno a esso. Nessun vincolo: gli stessi dati escono dall’app anche come PDF, DXF, CSV e XLSX.

  • Schema: shared/schema/project.schema.json (JSON Schema). Ogni progetto di esempio è verificato con esso nei test.
  • Versione attuale del formato: 7. La versione è il campo version all’inizio del file.

Scrittura stabile, adatta ai confronti

Il file è scritto sempre nello stesso modo, così una modifica al disegno dà una piccola modifica al file:

  • chiavi sempre nello stesso ordine, rientro di due spazi, un a capo alla fine;
  • oggetti ed elenchi brevi su una riga (fino a 100 caratteri), quelli più lunghi espansi un elemento per riga;
  • elenchi ordinati dove l’ordine non ha significato (dati dei dispositivi per designazione, cavi per designazione), e tenuti nell’ordine del disegno dove lo ha (pagine, elementi di una pagina);
  • nessun orario né percorso specifico del computer dentro il progetto.

Elementi di una pagina

Ogni elemento ha un id, un kind e i propri campi, in millimetri della pagina (origine in alto a sinistra, y verso il basso):

symbol (simbolo di libreria, posizione, rotazione, specchiatura, designazione, luogo, testo di funzione, valore), box (scatola nera o connettore con pin), wire (spezzata ortogonale, potenziale, numero, tipo di filo, cavo e conduttore), junction, text, line, rect, circle, table, image, warning (segnale di avvertimento), form (un foglio dati legato ai campi del progetto), report (un report dal vivo stampato sulla pagina) e cab (un elemento del layout del quadro).

Report, riferimenti incrociati, distinta, morsettiere ed elenchi cavi non sono salvati: sono calcolati dallo schema ogni volta, quindi non possono mai essere in disaccordo con esso.

Versioni e migrazioni

Quando il formato cambia, la versione aumenta di uno e una migrazione trasforma la versione *n* in *n + 1*. Aprendo un file più vecchio si eseguono tutte le migrazioni in sequenza, in memoria; il file è scritto nella nuova versione solo quando salvi. Un file di un CablePilot più recente viene rifiutato con un messaggio chiaro (aggiorna l’app), mai letto a metà. Un file danneggiato viene segnalato con ciò che non va e non viene modificato.

Accanto al progetto

Questi restano nella cartella dati di CablePilot sul tuo computer, non nel progetto:

  • Salvataggio automatico e recupero: una copia mentre lavori; dopo un arresto anomalo, CablePilot propone di recuperarla.
  • Cronologia: un backup giornaliero e le versioni a cui dai un nome (Cronologia), confrontate con la copia di lavoro e ripristinate in un solo passo annullabile.
  • Libreria aziendale: i tuoi simboli, modelli, macro, articoli e modelli di layout, come file di dati nello stesso formato della libreria integrata.
  • Impostazioni: lingua, tema e disposizione dei pannelli; le chiavi API e le password ERP sono cifrate dal sistema operativo e mai scritte in chiaro.

Formati di scambio

  • PDF: il set di disegni o una pagina, vettoriale, in scala reale.
  • DXF: pagine in ingresso e in uscita; la piastra di montaggio per la foratura.
  • CSV e XLSX: ogni elenco (morsetti, cavi, fili, distinta, I/O PLC, marcatori, targhette, lista di prelievo).
  • Layout del quadro: JSON e CSV documentati, vedi formato di scambio del layout.
  • ERP: articoli e giacenze in ingresso, richieste di prenotazione in uscita, vedi collegamento ERP.
  • Liste tag PLC: XML di TIA Portal e testo CODESYS, in uscita e in ingresso con anteprima.
